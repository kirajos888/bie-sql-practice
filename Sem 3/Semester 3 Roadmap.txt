1. STORAGE LAYOUTS: ROW-ORIENTED VS. COLUMNAR
   * Row-Oriented Layout (OLTP / PostgreSQL / MySQL):
     - Writes full records sequentially on disk.
     - Optimized for single-row reads and fast transactional updates.
   * Columnar Layout (OLAP / Amazon Redshift / Apache Parquet / Athena):
     - Groups values of the same column together on contiguous disk blocks.
     - Why Kimball Needs Columnar: Queries like SUM(refund_amt) read ONLY the
       blocks containing refund_amt, skipping unneeded attributes on disk.

2. DISTRIBUTED PARTITIONING & DATA PLACEMENT
   * In S3 Data Lakes:
     - Partitioning maps to directory prefixes (e.g., s3://bucket/year=2026/month=07/).
     - Enables Partition Pruning: Engines (Athena) open only specific folders.
   * In Amazon Redshift:
     - DISTKEY (Hash Partitioning): Co-locates fact and dimension rows with matching
       keys on the same compute node slice (Zero-Shuffle Join).
     - DISTSTYLE ALL (Replication): Replicates small dimension tables across every
       node so joins execute locally in memory.

3. MUTABILITY, SSTABLES, AND APPEND-ONLY DATA LAKES
   * S3 Data Lakes are Append-Only:
     - Cannot modify individual bytes inside existing S3 files.
     - Updating data requires overwrite operations or modern Table Formats
       (Apache Iceberg / Delta Lake) using ACID manifest logs.
   * Amazon Redshift Append-Only Mechanics:
     - Updates/Deletes mark old row blocks as logically deleted in a bitmap and
       append new rows.
     - The VACUUM command reclaims deleted blocks in the background.
